# Session — 2026-04-09 (Phase 5a Path Nodes)

## Decisions
- Path-Node implementiert: Line / Circle / Arc als eigene Kategorie (violett `#7C3AED`)
- Camera bekommt `path` + `pathProgress` Input-Ports (via Kabel, KEIN Mode oder Noderef-Dropdown)
- Light (Directional/Point) bekommt ebenfalls `path` + `pathProgress` Input-Ports
- Circle wraps kontinuierlich — pathProgress wird NICHT auf [0,1] geclippt im LiveEvaluator
- Look Ahead Property nur bei Free-Camera sichtbar (`visibleWhen: { uniform: 'mode', equal: 0 }`)
- Path Gizmos: TransformControls (translate only) auf PathObjects, gleiche Architektur wie LightObject
- PathObjects sichtbar im SceneExplorer (SCENE_CATEGORIES erweitert um 'path')
- EditorView: Feste Viewport-Lichter (ambient 0.4 + directional von [5,5,5]) — keine Scene-Lichter sichtbar
- Wireframe-Mode: `meshBasicMaterial` statt `meshStandardMaterial` mit wireframe=true → kein Shading
- `visibleWhen` kann nicht auf Port-Verbindungsstatus reagieren → zukünftiger Task (Position X/Y/Z bleiben sichtbar auch wenn path connected)

## Bugs gefunden & gefixt
- Kamera-Path zuerst als Mode 2 mit Noderef implementiert (falsch) → korrigiert: Port-basiert via Kabel
- Circle stoppte nach einer Runde → pathProgress wurde im LiveEvaluator geclampt → Clamping entfernt
- `glTF/` Verzeichnis in .gitignore ergänzt (70MB Test-Assets)

## Open items

- Phase 5b: glTF Import Node
